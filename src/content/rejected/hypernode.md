Hypernode is a Dutch platform built for Magento and Shopware, descended from Byte's engineering and now part of team.blue. It publishes extensive documentation, a deployment tool built on Deployer, PHP and Python API clients, a Docker development environment and n98-magerun plugins.

**Criterion 6 — two independent artifacts — could not be satisfied,** which is a surprising result for a platform this embedded in a framework ecosystem. Searched: GitHub repository search and code search for the platform name, and the pipelines documented in its own knowledge base. Every artifact found — hypernode-deploy, hypernode-docker, hypernode-vagrant, hypernode-api-php, hypernode-api-python, hypernode-magerun — is published by the ByteInternet or Hypernode organisations. That the tooling is excellent does not make it independent, and first-party work does not count under the criterion as written.

A second problem is separate from the criterion: the pricing page renders its figures client-side and no plan price could be read from any first-party page without JavaScript, so criterion 3 could not be confirmed either.

This rejection is the clearest illustration of how the criterion behaves. A platform whose vendor does all the integration work itself scores worse than one whose users had to write their own. **An agency-maintained package, a Magento or Shopware documentation reference, an independent talk or an issue-tracker thread would be enough to list it.**
