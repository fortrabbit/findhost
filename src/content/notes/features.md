description: What comes with the hosting beyond running the code — collaboration, staging, domains, DNS, email, a CDN, a test URL — and why none of them is a record of its own.
---

A hosting plan is rarely the whole job. Some of this is a second invoice — domains have to be registered somewhere, DNS served by someone, email run on a machine that is not the one serving the site, and most application platforms include none of the three while a shared host often includes all of them. The rest is whether the platform expects more than one person: **collaboration** is recorded because a platform where the account *is* the login is a different product from one where a team, or a client, has a place of their own, and no pricing page says which it is until somebody needs it. **Staging** is the same kind of fact — for a good many providers it is what the next tier up is for. Each is recorded as included, sold as an add-on, or not offered, because "they will sell it separately" is the ordinary answer and a yes-or-no has nowhere to put it. A record showing nothing here is one nobody has checked, not one with seven noes. None of these gets a record of its own: a registrar, a mail host and a git forge each fail the [first criterion](/about/), since nothing of the customer's is deployed or run, so they appear here as something a host includes or leaves you to buy and never as a provider. Git hosting has no field at all, because the question people filter on is whether a host [deploys from a commit](/deployment/git/) rather than where the commit lives — and [managed databases](/databases/) are the exception that shows the shape, earning a facet because the answer is which engine, not whether.
